# 利润报表按天同步修改说明

## 修改背景
原设计中使用 `sync_start_date` 和 `sync_end_date` 来标记数据的同步日期范围，现改为按天同步，使用单个 `sync_date` 字段，并以 `sync_date + asin` 作为唯一键。

## 主要修改内容

### 1. 数据库结构修改

#### 1.1 字段变更
- **删除字段**：`sync_start_date`, `sync_end_date`
- **新增字段**：`sync_date` (DATE类型，表示数据所属日期)

#### 1.2 唯一索引
```sql
-- 创建唯一索引（sync_date + asin）
CREATE UNIQUE INDEX uk_profit_report_date_asin 
ON amazon_profit_report(sync_date, asin) 
WHERE deleted = FALSE;
```

### 2. 实体类修改

#### ProfitReportDO.java
```java
// 原字段
// private LocalDate syncStartDate;
// private LocalDate syncEndDate;

// 新字段
private LocalDate syncDate;  // 同步日期（数据所属日期，按天）
```

### 3. 同步逻辑修改

#### 3.1 按天循环同步
```java
// 原逻辑：一次性同步整个日期范围
// 新逻辑：按天循环同步
LocalDate currentDate = syncReqVO.getStartDate();
LocalDate endDate = syncReqVO.getEndDate();

while (!currentDate.isAfter(endDate)) {
    // 调用API获取当天数据
    List<ProfitReportDTO> apiData = lingXingApiService.getAllProfitReportData(
        currentDate.toString(),
        currentDate.toString(),  // 同一天
        syncReqVO.getSids(),
        syncReqVO.getAsins()
    );
    
    // 处理数据...
    currentDate = currentDate.plusDays(1);
}
```

#### 3.2 唯一键冲突处理
- **全量同步(FULL)**：先删除当天所有数据，再插入新数据
- **增量同步(INCREMENTAL)**：跳过已存在的记录（基于 sync_date + asin）

```java
// 增量同步时过滤已存在记录
if ("INCREMENTAL".equals(syncReqVO.getSyncType())) {
    entities = filterExistingRecords(entities, currentDate);
}
```

### 4. Mapper 查询方法修改

#### 4.1 聚合查询
```java
// 使用 sync_date 进行日期范围查询
default List<ProfitReportDO> selectListForAggregation(
    LocalDate startDate, LocalDate endDate,
    List<String> sids, List<String> asins, List<String> skus) {
    return selectList(new LambdaQueryWrapperX<ProfitReportDO>()
        .betweenIfPresent(ProfitReportDO::getSyncDate, 
            new LocalDate[]{startDate, endDate})
        .inIfPresent(ProfitReportDO::getSid, sids)
        .inIfPresent(ProfitReportDO::getAsin, asins)
        .inIfPresent(ProfitReportDO::getLocalSku, skus));
}
```

#### 4.2 删除数据
```java
// 按日期删除数据
default int deleteByDateAndSids(LocalDate syncDate, List<String> sids) {
    return delete(new LambdaQueryWrapperX<ProfitReportDO>()
        .eqIfPresent(ProfitReportDO::getSyncDate, syncDate)
        .inIfPresent(ProfitReportDO::getSid, sids));
}
```

#### 4.3 查询已存在记录
```java
// 查询指定日期已存在的ASIN列表
default List<String> selectExistingAsins(LocalDate syncDate, List<String> asins) {
    return selectObjs(new LambdaQueryWrapperX<ProfitReportDO>()
        .eq(ProfitReportDO::getSyncDate, syncDate)
        .in(ProfitReportDO::getAsin, asins)
        .select(ProfitReportDO::getAsin));
}
```

## 优势

1. **数据粒度更细**：按天存储，便于按日期维度分析
2. **唯一性保证**：sync_date + asin 作为唯一键，避免重复数据
3. **同步更灵活**：可以重新同步某一天的数据而不影响其他日期
4. **查询更高效**：按日期查询时性能更好
5. **数据管理更清晰**：每条记录对应特定日期的特定产品数据

## 注意事项

1. **数据库迁移**：如果已有数据，需要执行数据迁移脚本
2. **API调用频率**：按天同步会增加API调用次数，需注意API限制
3. **事务处理**：建议每天的数据作为一个事务处理
4. **错误恢复**：如果某天同步失败，可以单独重试该天

## 测试要点

1. 测试日期范围同步（多天）
2. 测试单天重复同步（验证唯一键约束）
3. 测试增量同步（验证跳过已存在记录）
4. 测试全量同步（验证删除旧数据）
5. 测试聚合查询（验证日期范围查询）

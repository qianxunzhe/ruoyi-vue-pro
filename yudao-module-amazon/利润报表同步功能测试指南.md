# 利润报表同步功能测试指南

## 测试前准备

1. **确保服务正常启动**
   - 启动 Spring Boot 应用
   - 确认数据库连接正常
   - 确认领星 API 配置正确

2. **获取访问令牌**
   - 使用系统登录接口获取 access_token
   - 或者从浏览器开发者工具中获取已登录用户的 token

## 功能测试步骤

### 1. 测试数据同步

#### 1.1 增量同步测试
```bash
curl -X POST "http://localhost:48080/admin-api/amazon/profit-report/sync" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {your_token}" \
  -d '{
    "startDate": "2024-08-15",
    "endDate": "2024-08-17",
    "syncType": "INCREMENTAL",
    "sids": [101, 102]
  }'
```

**预期结果：**
- 返回同步的数据条数
- 数据库中新增相应记录
- 不删除已有数据

#### 1.2 全量同步测试
```bash
curl -X POST "http://localhost:48080/admin-api/amazon/profit-report/sync" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {your_token}" \
  -d '{
    "startDate": "2024-08-01",
    "endDate": "2024-08-31",
    "syncType": "FULL",
    "sids": [101]
  }'
```

**预期结果：**
- 删除指定日期范围和店铺的旧数据
- 重新同步新数据
- 返回同步的数据条数

### 2. 测试数据聚合查询

#### 2.1 SKU维度聚合
```bash
curl -X POST "http://localhost:48080/admin-api/amazon/profit-report/aggregate/sku" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {your_token}" \
  -d '{
    "startDate": "2024-08-01",
    "endDate": "2024-08-31",
    "pageNo": 1,
    "pageSize": 20
  }'
```

**预期结果：**
- 返回按SKU聚合的数据
- 包含销售数量、金额、利润等汇总信息
- 支持分页

#### 2.2 SPU维度聚合
```bash
curl -X POST "http://localhost:48080/admin-api/amazon/profit-report/aggregate/spu" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {your_token}" \
  -d '{
    "startDate": "2024-08-01",
    "endDate": "2024-08-31",
    "sids": [101, 102],
    "pageNo": 1,
    "pageSize": 10
  }'
```

**预期结果：**
- 返回按SPU聚合的数据
- 包含SKU列表和数量
- 计算综合毛利率和ACOS

#### 2.3 店铺维度聚合
```bash
curl -X POST "http://localhost:48080/admin-api/amazon/profit-report/aggregate/shop" \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer {your_token}" \
  -d '{
    "startDate": "2024-08-01",
    "endDate": "2024-08-31",
    "pageNo": 1,
    "pageSize": 10
  }'
```

**预期结果：**
- 返回按店铺聚合的数据
- 包含SKU和ASIN数量统计
- 显示店铺整体经营情况

## 异常情况测试

### 1. 日期范围验证
- 测试超过31天的日期范围（应自动分批）
- 测试未来日期（应返回错误）
- 测试结束日期早于开始日期（应返回错误）

### 2. API限制测试
- 测试超过10个ASIN（应自动分批）
- 测试空ASIN列表（应获取所有数据）

### 3. 数据完整性测试
- 验证聚合数据的准确性
- 检查货币代码一致性
- 确认其他费用JSON格式正确

## 性能测试

### 大数据量测试
1. 同步整月数据（31天）
2. 查询大量SKU的聚合数据
3. 验证分页功能的性能

### 并发测试
1. 多用户同时查询
2. 同步和查询并发执行
3. 验证数据一致性

## 数据库验证

直接查询数据库验证：
```sql
-- 查看同步的数据
SELECT COUNT(*) FROM amazon_profit_report 
WHERE sync_start_date >= '2024-08-01' 
AND sync_end_date <= '2024-08-31';

-- 验证聚合逻辑
SELECT local_sku, 
       SUM(total_sales_quantity) as total_qty,
       SUM(total_sales_amount) as total_amount,
       SUM(gross_profit) as total_profit
FROM amazon_profit_report
WHERE sync_start_date >= '2024-08-01'
GROUP BY local_sku
ORDER BY total_amount DESC;
```

## 注意事项

1. 首次测试建议使用较小的日期范围
2. 注意领星API的调用频率限制
3. 确保测试环境的数据库有足够空间
4. 测试后记得清理测试数据

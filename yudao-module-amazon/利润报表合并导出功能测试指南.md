# 利润报表合并导出功能测试指南

## 功能概述
新增了利润报表导出时合并历史Excel文件的功能。当用户选择合并历史数据时，系统会将新查询的数据追加到历史Excel文件的对应Sheet中，每个时间段的数据作为一个新列。

## 接口变更说明

### 1. 接口地址和方法
- **原接口**: GET `/amazon/profit-report/export-aggregate-excel`
- **新接口**: POST `/amazon/profit-report/export-aggregate-excel`
- **Content-Type**: `multipart/form-data`

### 2. 请求参数

| 参数名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| groupBy | String | 否 | 聚合维度，默认"SPU" |
| startDate | String | 否 | 开始日期，格式：yyyy-MM-dd |
| endDate | String | 否 | 结束日期，格式：yyyy-MM-dd |
| sid | String | 否 | 店铺ID列表，逗号分隔 |
| mergeHistory | Boolean | 否 | 是否合并历史文件，默认false |
| exportFormat | String | 否 | 导出格式，默认"STANDARD" |
| historyFile | File | 否 | 历史Excel文件（当mergeHistory=true时需要） |

## 测试场景

### 场景1：不合并历史文件（与原有功能相同）
```
POST /amazon/profit-report/export-aggregate-excel
FormData:
  - groupBy: SPU
  - startDate: 2025-09-01
  - endDate: 2025-09-07
  - sid: 10730,10565,10549
  - mergeHistory: false
```

**预期结果**：
- 生成新的Excel文件，包含指定日期范围的数据
- 每个SPU一个Sheet
- 数据格式与原有导出格式相同

### 场景2：合并历史文件
```
POST /amazon/profit-report/export-aggregate-excel
FormData:
  - groupBy: SPU
  - startDate: 2025-09-08
  - endDate: 2025-09-14
  - sid: 10730,10565,10549
  - mergeHistory: true
  - historyFile: [选择之前导出的Excel文件]
```

**预期结果**：
- 读取历史Excel文件
- 在每个已存在的SPU Sheet中，新增一列"2025-09-08至2025-09-14"
- 新列包含新日期范围的数据
- 如果有新的SPU（历史文件中不存在），创建新的Sheet
- 保持原有数据不变，仅追加新列

### 场景3：多次合并
1. 第一次导出（2025-09-01至2025-09-07）
2. 第二次合并（2025-09-08至2025-09-14）
3. 第三次合并（2025-09-15至2025-09-21）

**预期结果**：
- Excel文件中每个SPU Sheet包含三列数据
- 列标题分别为各个日期范围
- 数据按时间顺序排列

## 使用Postman测试

1. 创建新的POST请求
2. URL: `http://localhost:48080/admin-api/amazon/profit-report/export-aggregate-excel`
3. Headers添加: `Authorization: Bearer {token}`
4. Body选择`form-data`
5. 添加参数：
   - 文本参数：groupBy、startDate、endDate、sid、mergeHistory
   - 文件参数：historyFile（类型选择File）

## 注意事项

1. **文件大小限制**：上传的历史Excel文件不应超过10MB
2. **SPU匹配**：系统按SPU名称匹配Sheet，确保SPU名称一致
3. **数据格式**：历史文件必须是之前通过本系统导出的Excel文件
4. **权限要求**：需要有`amazon:profit-report:export`权限

## 错误处理

| 错误情况 | 错误提示 |
|----------|----------|
| 历史文件格式错误 | "读取Excel文件失败" |
| 没有查询到数据 | "没有可导出的数据" |
| 合并失败 | "合并Excel文件失败：{具体原因}" |

## 开发者说明

合并逻辑的核心实现在`ExcelMergeUtils.mergeExcelSheets()`方法中：
1. 读取历史Excel文件的所有Sheet数据
2. 匹配新数据与历史Sheet（按SPU名称）
3. 在匹配的Sheet中追加新列
4. 处理新增的SPU（创建新Sheet）
5. 保持数据行的对应关系（按项目名称匹配）
